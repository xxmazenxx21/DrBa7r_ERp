USERS MODULE API Documentation
==============================

Base URL
--------
https://drba7rerp-production.up.railway.app

Module Source
-------------
src/users (controller: UsersController, service: UsersService)


Overview
--------
This module manages system users (accounts used to log into the ERP).
Every user account can optionally be linked to an Employee record and/or a Branch,
and always carries one Role.

All endpoints under /users require a valid JWT Bearer token
(except nothing - even /users/login requires a token, see warning below).


Authentication
--------------
Every request to /users* must include this header:

    Authorization: Bearer <access_token>

How to get a token (the real login endpoint):

    POST /auth/login        <-- PUBLIC (no token needed)

    Request Body:
    {
      "username": "drba7r",
      "password": "drba7r12345"
    }

    Success Response (201):
    {
      "access_token": "eyJhbGciOiJIUzI1NiIs...",
      "user": {
        "id": "cm4auth123...",
        "username": "drba7r",
        "role": "SUPERADMIN"
      }
    }

    Error (401 - wrong username/password or deleted user):
    {
      "message": "Invalid credentials",
      "error": "Unauthorized",
      "statusCode": 401
    }

Use the returned access_token in the Authorization header for all /users calls.


Role Values (allowed for the "role" field)
------------------------------------------
    SUPERADMIN
    ADMIN
    ACCOUNTENT
    SALLES      <-- note the spelling (S-A-L-L-E-S), exactly as stored in the database
    USER        <-- default if not provided at DB level, but required in the create DTO

WARNING: do NOT send "SALES" (single L) - it will be rejected by the database.


---------------------------------------------------------
1) Create User
---------------------------------------------------------
Method: POST
URL: /users
Access: Requires Bearer token

Validation Rules (all applied by DTO):
- username : required string (must be globally unique)
- password : required string, minimum 6 characters
- role     : required enum (SUPERADMIN, ADMIN, ACCOUNTENT, SALLES, USER)
- email    : optional, must be valid email format (unique if provided)
- employeeId : optional string (links the account to an employee, unique per user)
- branchId   : optional string (must be an existing branch id)

Request Example:
{
  "username": "ahmed.sales",
  "password": "secret123",
  "role": "SALLES",
  "email": "ahmed@example.com",
  "employeeId": "cm4employee789",
  "branchId": "cm4branch123"
}

Success Response (201):
{
  "message": "user created successfully"
}

IMPORTANT: the response contains ONLY the message - the new user's id is NOT
returned. If you need the id, call GET /users afterwards and find the user by
username.

Error Cases:
- Missing/invalid fields          -> 400 (validation error, see Error Responses section)
- Duplicate username/email        -> 500 (database unique constraint)
- Non-existing employeeId/branchId-> 500 (foreign key constraint)
- No/invalid token                -> 401


---------------------------------------------------------
2) Login (duplicate endpoint inside /users)
---------------------------------------------------------
Method: POST
URL: /users/login
Body: same shape as /auth/login ({ username, password })
Returns: same shape as /auth/login ({ access_token, user })

*** WARNING ***
This endpoint is NOT marked as public, so it REQUIRES a Bearer token to be
called - which makes it useless for an initial login.
Always use POST /auth/login instead. This endpoint exists in the code but
should not be used by the frontend.


---------------------------------------------------------
3) Get All Users
---------------------------------------------------------
Method: GET
URL: /users
Access: Requires Bearer token

Description: Returns all active (not soft-deleted) users.
Soft-deleted users are excluded automatically.

Success Response (200):
{
  "data": [
    {
      "id": "cm4auth123...",
      "username": "drba7r",
      "email": "drba7r@example.com",
      "role": "SUPERADMIN",
      "employeeId": null,
      "branchId": null,
      "lastLoginDate": "2026-08-21T18:30:00.000Z",
      "createdAt": "2026-08-21T18:25:33.000Z",
      "updatedAt": "2026-08-21T18:25:33.000Z"
    }
  ],
  "message": "Users retrieved successfully"
}

Note: the password field is NEVER returned.


---------------------------------------------------------
4) Get User By ID
---------------------------------------------------------
Method: GET
URL: /users/:id
Access: Requires Bearer token

Path Parameter:
- id : the user id (cuid string, e.g. "cm4auth123...")

Example Request:
GET /users/cm4auth123

Success Response (200):
{
  "data": {
    "id": "cm4auth123...",
    "username": "drba7r",
    "email": "drba7r@example.com",
    "role": "SUPERADMIN",
    "employeeId": null,
    "branchId": null,
    "lastLoginDate": "2026-08-21T18:30:00.000Z",
    "createdAt": "2026-08-21T18:25:33.000Z",
    "updatedAt": "2026-08-21T18:25:33.000Z"
  },
  "message": "User retrieved successfully"
}

Error Response (404 - not found OR soft-deleted):
{
  "statusCode": 404,
  "message": "User with id cm4auth123 not found",
  "error": "Not Found"
}


---------------------------------------------------------
5) Update User
---------------------------------------------------------
Method: PATCH
URL: /users/:id
Access: Requires Bearer token

Description: Partial update - send only the fields you want to change.
All fields from Create User are allowed (username, password, role, email,
employeeId, branchId), each one optional.

Request Example (change role and email only):
{
  "role": "ADMIN",
  "email": "newmail@example.com"
}

Success Response (200):
{
  "data": {
    "id": "cm4auth123...",
    "username": "drba7r",
    "email": "newmail@example.com",
    "role": "ADMIN",
    "employeeId": null,
    "branchId": null,
    "lastLoginDate": "2026-08-21T18:30:00.000Z",
    "createdAt": "2026-08-21T18:25:33.000Z",
    "updatedAt": "2026-08-21T18:31:00.000Z"
  },
  "message": "User updated successfully"
}

Error Cases:
- User not found / soft-deleted -> 404
- Invalid role / bad email      -> 400
- Duplicate username/email      -> 500

CAUTION: if you send "password" in this request it will be stored WITHOUT
hashing (backend limitation at the moment). Prefer not changing passwords
through this endpoint until this is fixed.


---------------------------------------------------------
6) Delete User
---------------------------------------------------------
Method: DELETE
URL: /users/:id
Access: Requires Bearer token

Description: SOFT delete. The record stays in the database but gets
deletedAt timestamped, so it disappears from GET /users and GET /users/:id,
and the user can no longer log in.

Success Response (200):
{
  "message": "User deleted successfully"
}

Error Response (404 - not found or already deleted):
{
  "statusCode": 404,
  "message": "User with id cm4auth123 not found",
  "error": "Not Found"
}


---------------------------------------------------------
Related APIs you may need BEFORE calling /users
---------------------------------------------------------

A) You need "branchId":
   Step 1 - list all branches:
       GET /branch
       -> take the id from: response.data[i].id

B) You need "employeeId":
   Employees are listed PER BRANCH, so you need a branchId first.
   Step 1 - GET /branch                      -> pick a branch: data[i].id
   Step 2 - GET /employees/branch/{branchId} -> pick an employee: data[i].id
            (only active/not-deleted employees of that branch are returned,
             each item contains id, code, fullName, nationalId, jobTitle...)

C) You need a token before anything else:
   POST /auth/login  (see Authentication section above)


---------------------------------------------------------
Error Responses (general)
---------------------------------------------------------

401 Unauthorized (missing/expired/invalid token on ANY /users endpoint):
{
  "message": "Unauthorized",
  "statusCode": 401
}

400 Bad Request (validation failure - "message" is an ARRAY of errors):
{
  "message": [
    "password must be longer than or equal to 6 characters",
    "role must be one of the following values: SUPERADMIN, ADMIN, ACCOUNTENT, SALES, USER"
  ],
  "error": "Bad Request",
  "statusCode": 400
}
(Note: the validation message lists "SALES" but the database actually accepts
"SALLES" - always send SALLES.)

403 Forbidden (token valid but role not allowed - reserved for future
role-restricted endpoints via the RolesGuard):
{
  "message": "You do not have the required roles to access this resource",
  "error": "Forbidden",
  "statusCode": 403
}

500 Internal Server Error (e.g. duplicate username, invalid foreign key):
{
  "message": "Internal server error",
  "statusCode": 500
}


---------------------------------------------------------
Frontend Integration Checklist
---------------------------------------------------------
1. Login via POST /auth/login -> store access_token.
2. Attach "Authorization: Bearer <token>" to every /users request.
3. Handle 401 globally: clear session and redirect to login screen.
4. After creating a user, re-fetch GET /users to obtain the new id.
5. Remember: DELETE is soft - the user simply stops appearing in lists.
6. Valid roles: SUPERADMIN | ADMIN | ACCOUNTENT | SALLES | USER.
