PART 1 - NEW ENUM VALUES (send / receive the TEXT value)
=====================================================================
They will appear in the Week 3 documents and in the item card
(GET /stock-movements/item-card, GET /stock-movements?type=...).

DocumentType (document number prefix / sourceType of a stock movement)
  existing:  PQ = عرض سعر شراء, PI = فاتورة شراء, PR = مرتجع شراء
  new:       SQ = عرض سعر بيع        (Sales Quotation)
             SI = فاتورة بيع         (Sales Invoice)
             SR = مرتجع بيع          (Sales Return)
             ST = تحويل مخزني        (Stock Transfer)
             SC = جرد                (Stock Count)

StockMovementType (item card "type")
  existing:  OPENING = رصيد افتتاحي, ADJUSTMENT = تسوية, PURCHASE = شراء,
             PURCHASE_CANCEL = إلغاء فاتورة شراء, PURCHASE_RETURN = مرتجع شراء,
             PURCHASE_RETURN_CANCEL = إلغاء مرتجع شراء
  new:       SALE                 = بيع               (-)  a sales invoice is posted
             SALE_CANCEL          = إلغاء فاتورة بيع   (+)
             SALE_RETURN          = مرتجع بيع          (+)
             SALE_RETURN_CANCEL   = إلغاء مرتجع بيع    (-)
             TRANSFER_OUT         = تحويل صادر         (-)  out of the source warehouse
             TRANSFER_IN          = تحويل وارد         (+)  into the destination warehouse
             TRANSFER_OUT_CANCEL  = إلغاء تحويل صادر   (+)  back into the source
             TRANSFER_IN_CANCEL   = إلغاء تحويل وارد   (-)  out of the destination

A stock count (جرد) has no type of its own: it writes ADJUSTMENT (تسوية)
movements with sourceType "SC" (show the count number from sourceCode).

Add these labels to the item card and the movements filter now.

PART 2 - SALES QUOTATIONS (عروض أسعار البيع)  - doc/week3/sales-quotations.txt
=====================================================================
    POST   /sales-quotations             new DRAFT quotation with its lines
    GET    /sales-quotations             list (PAGINATED; filters customerId,
                                         branchId, status, dateFrom, dateTo,
                                         search = code / customer name / notes)
    GET    /sales-quotations/:id         header + lines + isExpired
    PATCH  /sales-quotations/:id         edit (DRAFT / SENT only; "lines" REPLACES all lines)
    PATCH  /sales-quotations/:id/status  { "status": "SENT" | "ACCEPTED" | "REJECTED" }
    DELETE /sales-quotations/:id         soft delete (not when CONVERTED)
  The mirror of purchase quotations (doc/week2/week2flow.txt): same screen,
  same lines table, same statuses (DRAFT -> SENT -> ACCEPTED / REJECTED) and
  errors - with customerId (العميل, from GET /customer) instead of supplierId,
  and SQ numbers. No effect on stock or money.
  The user types unitPrice (سعر البيع): suggest it from the product's
  retailPrice / wholesalePrice. No price level per customer.
  Example: 5 cartons x 180, discount 5%, tax 14% -> SQ-2026-000001,
  subTotal 900, discountValue 45, taxValue 119.70, netTotal 974.70.
  DRAFT -> ACCEPTED directly -> 409 INVALID_STATUS.
  convert-to-invoice comes with Task 4 (after sales invoices).

Arabic labels (new keys)
  Sales quotation: code = رقم العرض, quotationDate = تاريخ العرض,
                   validUntil = صالح حتى, status = الحالة, customerId = العميل,
                   branchId = الفرع, warehouseId = المخزن, subTotal = الإجمالي,
                   discountPercent = نسبة الخصم %, discountValue = قيمة الخصم,
                   taxPercent = نسبة الضريبة %, taxValue = قيمة الضريبة,
                   netTotal = الصافي, convertedToInvoiceId = الفاتورة الناتجة,
                   notes = ملاحظات, createdBy = أنشأه, modifiedBy = عدّله,
                   isExpired = منتهي الصلاحية
  Quotation line:  productId = الصنف, itemUnitId = الوحدة, unitFactor = معامل الوحدة,
                   quantity = الكمية, unitPrice = سعر البيع للوحدة,
                   discountPercent = نسبة خصم البند %, discountValue = قيمة خصم البند,
                   lineTotal = إجمالي البند
  QuotationStatus: DRAFT = مسودة, SENT = مُرسل, ACCEPTED = مقبول,
                   REJECTED = مرفوض, CONVERTED = تم التحويل لفاتورة

PART 3 - SALES INVOICES (فواتير البيع)  - doc/week3/sales-invoices.txt
=====================================================================
    POST   /sales-invoices                 new DRAFT invoice with its lines
    GET    /sales-invoices                 list (PAGINATED; filters customerId,
                                           branchId, warehouseId, status,
                                           paymentType, dateFrom, dateTo,
                                           search = code / customer name / notes)
    GET    /sales-invoices/:id             header + lines + grossProfit
    PATCH  /sales-invoices/:id             edit (DRAFT only; "lines" REPLACES all)
    DELETE /sales-invoices/:id             soft delete (DRAFT only)
    POST   /sales-invoices/:id/post        ترحيل: DRAFT -> POSTED, stock goes DOWN
    POST   /sales-invoices/:id/cancel      إلغاء: POSTED -> CANCELLED, stock comes back
    GET    /sales-invoices/:id/returnable  per line: sold / returned / remaining
  The mirror of purchase invoices: same form (header + payment + currency +
  lines table + totals box), same statuses and buttons. Differences:
  customerId (العميل), lines use unitPrice (سعر البيع), no supplier invoice
  number / batch / expiry date, and the stock goes the other way.
  The client NEVER sends a cost: POST saves it from the warehouse average
  (stockUnitCost, lineCost, totalCost); grossProfit is shown on GET :id
  (null while DRAFT). Selling below cost is allowed (no warning); creditLimit
  is not checked until Week 4.
  Example: 5 cartons x 180, discount 5%, tax 14%, CREDIT -> SI-2026-000001,
  net 974.70, remaining 974.70. POST -> item card SALE -60 at 10.6818
  (Maadi 218 -> 158), totalCost 640.91, grossProfit 214.09. POST again -> 409.
  20 cartons with only 158 brushes -> POST gives 400 INSUFFICIENT_STOCK
  (field lines.0.quantity) and nothing changes. CANCEL -> SALE_CANCEL +60 at
  10.6818 (the cost they left with) -> Maadi 218.
  UI: show totalCost / grossProfit / line costs read only on POSTED invoices
  (Week 5 will hide them from SALES / USER); hide paidAmount for CASH.

Changed endpoints (BEFORE / AFTER)
  DELETE /customer/:id
    BEFORE: 200 for any active customer
    AFTER:  400 while any (not deleted) sales invoice uses the customer
      { "statusCode": 400, "message": "Customer is used by 3 sales invoice(s) and cannot be deleted", "error": "Bad Request", "code": "BAD_REQUEST", "field": null }
      Arabic: لا يمكن حذف العميل لأن عليه فواتير بيع
  DELETE /currency/:id
    BEFORE: refused only when purchase invoices use it
    AFTER:  also refused when sales invoices use it
      { "statusCode": 400, "message": "Currency is used by 1 sales invoice(s) and cannot be deleted", "error": "Bad Request", "code": "BAD_REQUEST", "field": null }

Arabic labels (new keys)
  Sales invoice:  code = رقم الفاتورة, invoiceDate = تاريخ الفاتورة,
                  dueDate = تاريخ الاستحقاق, paymentType = طريقة الدفع (CASH نقدي / CREDIT آجل),
                  customerId = العميل, warehouseId = المخزن, currencyId = العملة,
                  exchangeRate = سعر الصرف, paidAmount = المدفوع,
                  remainingAmount = المتبقي على العميل, totalCost = تكلفة البضاعة المباعة,
                  grossProfit = مجمل الربح, postedDate / postedBy = تاريخ الترحيل / رحّلها,
                  cancelledDate / cancelledBy = تاريخ الإلغاء / ألغاها
  Invoice line:   unitPrice = سعر البيع للوحدة, baseQuantity = الكمية بالقطعة,
                  stockUnitCost = تكلفة القطعة, lineCost = تكلفة البند
  DocumentStatus: DRAFT = مسودة, POSTED = مُرحّل, CANCELLED = ملغي
