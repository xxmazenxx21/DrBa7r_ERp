The Week 2 story (the flow)
---------------------------
A shop has 100 brushes in the Maadi warehouse at 10 each. Supplier "Nile"
sends a quotation: a carton (12 brushes) at 150. We accept it, turn it into a
purchase invoice for 10 cartons and post it. We find 2 broken cartons, so we
make a purchase return and post it. The system knows by itself that the
warehouse has 100 + 120 - 24 = 196 brushes at an average of 10.6818, and
every movement is in the item card.

  Purchase Quotation   --convert-->   Purchase Invoice   --return-->   Purchase Return
  عرض سعر شراء                         فاتورة شراء                       مرتجع شراء
  no effect                            POST: stock goes UP              POST: stock goes DOWN
                                       CANCEL: stock goes DOWN          CANCEL: stock comes back

  Setup before it: currency (EGP, default) -> product units (carton = 12)
  -> opening stock (POST /product-inventory: an OPENING movement).

The whole story runs as 16 requests: requests.http, section "WEEK 2 - THE BIG
TEST" (W2-0 ... W2-16), on an empty database. Final stock: 218
(100 + 120 - 24 + 24 - 2).

The 4 rules of the week
-----------------------
  1. Stock is always counted in the PRIMARY unit (pieces), even when you buy
     in cartons (quantity x factor).
  2. Only the server's stock service changes stock: every change is a stock
     movement (item card). You never send stock quantities to documents.
  3. The server computes every total. You send quantities, prices and
     percents only.
  4. A POSTED document is never edited or deleted. It can only be cancelled
     (an opposite movement), and it stays visible as CANCELLED.

Statuses
--------
  Purchase quotation (QuotationStatus):
      DRAFT مسودة --> SENT مُرسل --> ACCEPTED مقبول --> CONVERTED تم التحويل لفاتورة
                                \-> REJECTED مرفوض
      edit: DRAFT, SENT      delete: anything but CONVERTED      no stock effect

  Purchase invoice / purchase return (DocumentStatus):
      DRAFT مسودة --post--> POSTED مُرحّل --cancel--> CANCELLED ملغي
      edit / delete: DRAFT only

  A move that is not allowed -> 409 INVALID_STATUS.

  Stock effect:
      action                      movement type            stock
      --------------------------  -----------------------  -------------------
      POST /product-inventory     OPENING                  +  (opening balance)
      PATCH / DELETE stock        ADJUSTMENT               +/- (needs reason)
      post an invoice             PURCHASE                 +  (new average)
      cancel an invoice           PURCHASE_CANCEL          -
      post a return               PURCHASE_RETURN          -  (average unchanged)
      cancel a return             PURCHASE_RETURN_CANCEL   +  (same cost back)

  Blocks between documents:
      - an invoice with a POSTED return can't be cancelled (cancel the return first)
      - a return can't take more than bought - already returned (QUANTITY_EXCEEDED)
      - an invoice / return whose goods are not in the warehouse can't be
        cancelled / posted (INSUFFICIENT_STOCK)


Pagination (every NEW Week 2 list)
----------------------------------
Lists that can grow (documents, movements) are paginated. Query string:

    ?page=1&pageSize=20

    page      optional, whole number >= 1        (default 1)
    pageSize  optional, whole number 1 to 100    (default 20)
    anything else (0, 101, 1.5, "abc", unknown params) -> 400 VALIDATION_FAILED
      { "statusCode": 400, "message": ["pageSize must not be greater than 100"], "error": "Bad Request", "code": "VALIDATION_FAILED", "field": "pageSize" }

Response: "data" is NOT an array here, it is an object:

{
  "message": "...",
  "data": {
    "items": [ ... ],                 <-- the records of this page
    "meta": {
      "page": 1,
      "pageSize": 20,
      "total": 57,                    <-- records in ALL pages
      "totalPages": 3                 <-- 0 when there are no records
    }
  }
}

A page after the last one returns "items": [] (not an error).
Each module file says if its list is paginated. Week 1 lists are NOT
paginated (they still return a plain array), and small lists like
GET /currency are not either.


New error codes (Week 2)
------------------------
Same error shape as always: { statusCode, message, error, code, field }.
Three new codes for documents and stock:

  code                 status  when                                          suggested Arabic message
  -------------------  ------  --------------------------------------------  ---------------------------------------------
  INVALID_STATUS       409     the action is not allowed in the document's   لا يمكن تنفيذ العملية في حالة المستند الحالية
                               current status (e.g. posting an invoice that
                               is already posted). field "status"
  INSUFFICIENT_STOCK   400     not enough quantity in the warehouse          الكمية المتاحة في المخزن غير كافية
                               (posting a return, cancelling an invoice).
                               field "lines.N.quantity"
  QUANTITY_EXCEEDED    400     returning more than was bought                الكمية أكبر من المسموح بإرجاعه
                               (minus what was already returned).
                               field "lines.N.quantity"

Exact bodies are in each module file.
The full list of codes is in doc/week1/00-overview.txt (+ these three).


Totals are computed by the server
---------------------------------
For quotations, invoices and returns the frontend sends ONLY quantities,
prices and percents. The server computes every total:

    line total    = quantity x price - line discount
    subTotal      = sum of the line totals
    discountValue = subTotal x discountPercent / 100
                    (or the discountValue you send, if you send no percent)
    taxValue      = (subTotal - discountValue) x taxPercent / 100
    netTotal      = subTotal - discountValue + taxValue

Example: 10 cartons x 150, discount 10%, tax 14%
    subTotal 1500, discountValue 150, taxValue 189, netTotal 1539

Line totals keep 4 decimals, document totals 2 (rounded half up).
A discount percent outside 0-100, a tax percent outside 0-100, or a discount
value bigger than the amount -> 400 BAD_REQUEST (field = that field).
