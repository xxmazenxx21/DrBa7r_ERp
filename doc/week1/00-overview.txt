Base URL
--------
http://localhost:3000   (the backend runs on your machine with Docker, see README.md)

Authentication & access
-----------------------
EVERY endpoint requires a JWT and the SUPERADMIN role, EXCEPT these three
public endpoints:
    POST /auth/signup   (TEMPORARY - see auth.txt)
    POST /auth/login
    POST /users/login   (same as /auth/login)

Send the token on every request:

    Authorization: Bearer <access_token>

- No token / invalid token          -> 401
- Logged in but role is not SUPERADMIN -> 403 (on every endpoint)

First login on a fresh (Docker) database: username "admin", password "admin123"
(a SUPERADMIN created automatically when there are no users), or create your
own SUPERADMIN with POST /auth/signup.


Response shape (ALL successful responses)
-----------------------------------------
Every successful response, in every module, is exactly:

    { "message": string, "data": <object | array | null> }

    create / update / get one  -> data = the record (object)
    get all / list             -> data = array (empty [] when there is nothing)
    delete                     -> data = null
    signup                     -> data = the new user (never the password)
    login                      -> data = { access_token, user: { id, username, role } }

Example:
{
  "message": "Branch returned successfully",
  "data": { "id": "cm4branch123", "name": "فرع القاهره", ... }
}

Error responses have a different shape (see "Common error responses" below).


General rules
-------------
1. Codes are generated by the server. Do NOT send "code" (on create or
   update) for branch / category / item-unit / product / customer / supplier /
   employee. If you send one it is accepted but ignored. Formats:
     branch-123456, category-123456, unit-123456, PRD-123456,
     CUS-123456, SUP-123456, EMP-123456

2. Money / quantity fields (prices, quantity, costPrice, creditLimit,
   openingBalance...) are SENT as numbers but RETURNED as strings, e.g. "12.5".
   Convert with Number(...) / parseFloat(...) before doing math.
   Decimal places are LIMITED, too many -> 400 (the server never rounds):
     prices / quantities / costs (retailPrice, wholesalePrice,
       bulkWholesalePrice, reorderLimit, quantity, costPrice)   max 4
     money amounts (creditLimit, openingBalance)                max 2
   openingBalance can be negative (customer AND supplier, see their files).

3. Delete is ALWAYS a SOFT delete (every module): the record is hidden from
   lists and get-by-id returns 404, but it stays in the database (deletedAt is
   set).

4. IDs are strings, e.g. "cmwnwbnsj00002fmx5qtqdm7q".

5. PATCH = partial update: send only the fields you want to change.
   - field NOT sent   -> unchanged
   - field sent null  -> CLEARS it, for nullable fields only:
       branch.address; customer taxNumber / commercialRecord / phone / address;
       supplier taxNumber / contactPerson / phone / email; employee nationalId /
       jobTitle / hireDate; product barcode; user email / employeeId / branchId
   - null on any other field -> 400 VALIDATION_FAILED (that field can't be empty)

5b. An id that points to another record (categoryId, primaryItemUnitId,
   productId, employeeId, branchId in a BODY) must be an ACTIVE record.
   Missing OR soft-deleted -> 400 DOES_NOT_EXIST, field = that field name.
   (An id in the URL path, e.g. /inventory/branch/:branchId, answers 404 for
   missing or deleted, as before.)

6. Send ONLY the fields documented for each endpoint. Any unknown field is
   rejected with 400 "property <name> should not exist". This includes the
   query string of list endpoints (e.g. GET /inventory?foo=1 -> 400).

7. Request bodies are JSON:  Content-Type: application/json


Common error responses
----------------------
EVERY error response has the same 5 fields:

    {
      "statusCode": 404,                 HTTP status
      "message": "...",                  English text (an ARRAY for validation errors)
      "error": "Not Found",              HTTP status name
      "code": "NOT_FOUND",               stable code - use it to TRANSLATE / decide
      "field": null                      the field the error is about, or null
    }

Error codes:
    code                 status  field                 when
    -------------------  ------  --------------------  ------------------------------------------
    VALIDATION_FAILED    400     first invalid field   body/query failed validation, unknown field
    DOES_NOT_EXIST       400     the id field          a related id does not exist or is deleted
    BAD_REQUEST          400     null / the field      other bad requests (e.g. "is used by N
                                                       product(s)", malformed JSON, "branchId
                                                       must match the employee's branch")
    UNAUTHORIZED         401     null                  no token, bad token, wrong login
    FORBIDDEN            403     null                  logged in, but role is not SUPERADMIN
    NOT_FOUND            404     null                  record (or route) not found / deleted
    ALREADY_EXISTS       409     the unique field      value already used by an ACTIVE record
                         (400 for "Product inventory already exists", field "productId")
    BELONGS_TO_DELETED   409     the unique field      value belongs to a DELETED record
    INTERNAL_ERROR       500     null                  unexpected server problem

Translate with "code" (+ "field"), not by reading "message": the message text
may change, the codes will not. Arabic messages for every code:
doc/FRONTEND_WEEK1_UPDATE_2.txt

400 Validation error ("message" is an ARRAY):
{
  "statusCode": 400,
  "message": ["name should not be empty", "name must be a string"],
  "error": "Bad Request",
  "code": "VALIDATION_FAILED",
  "field": "name"
}

400 Unknown field sent ("message" is an ARRAY):
{
  "statusCode": 400,
  "message": ["property foo should not exist"],
  "error": "Bad Request",
  "code": "VALIDATION_FAILED",
  "field": "foo"
}

400 Related record not found (an id that does not exist OR is deleted, e.g.
categoryId on a product, productId on stock, branchId / employeeId on a user):
{ "statusCode": 400, "message": "categoryId does not exist", "error": "Bad Request", "code": "DOES_NOT_EXIST", "field": "categoryId" }

401 Unauthorized (no token, invalid token):
{ "statusCode": 401, "message": "Unauthorized", "error": "Unauthorized", "code": "UNAUTHORIZED", "field": null }

403 Forbidden (logged in, but the role is not SUPERADMIN):
{
  "statusCode": 403,
  "message": "You do not have the required roles to access this resource",
  "error": "Forbidden",
  "code": "FORBIDDEN",
  "field": null
}

404 Not found (message differs per module):
{ "statusCode": 404, "message": "Branch with id xxx not found", "error": "Not Found", "code": "NOT_FOUND", "field": null }

409 Conflict (a unique value is already used - username, email, barcode,
nationalId, employeeId on a user...). "message" names the field:
{ "statusCode": 409, "message": "username already exists", "error": "Conflict", "code": "ALREADY_EXISTS", "field": "username" }
If the value belongs to a DELETED record, the message says so (the deleted
record is NOT restored):
{ "statusCode": 409, "message": "nationalId belongs to a deleted employee", "error": "Conflict", "code": "BELONGS_TO_DELETED", "field": "nationalId" }
(also "username / email / employeeId belongs to a deleted user",
 "barcode belongs to a deleted product")

500 Internal server error (unexpected server problem only):
{ "statusCode": 500, "message": "Internal server error", "error": "Internal Server Error", "code": "INTERNAL_ERROR", "field": null }


Typical setup order (because of relations)
------------------------------------------
1. POST /auth/login                       -> token (data.access_token)
2. POST /branch                           -> branchId
3. POST /inventory/branch/:branchId       -> inventoryId (warehouse)
                                             (list all: GET /inventory)
4. POST /categories, POST /item-unit      -> categoryId, itemUnitId
5. POST /products                         -> productId
6. POST /product-inventory/inventory/:inventoryId  (put stock in warehouse)
7. POST /employees/branch/:branchId, POST /users, /customer, /supplier
                                             (list all employees: GET /employees)
