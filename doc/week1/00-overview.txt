ERP API - Overview (read this first)
====================================

Base URL
--------
Production:      https://drba7rerp-production.up.railway.app
Local (Docker):  http://localhost:3000


Files in this folder (one per module)
-------------------------------------
  auth.txt               POST /auth/login  (get your token here)
  users.txt              /users
  branch.txt             /branch
  inventory.txt          /inventory          (warehouses, belong to a branch)
  categories.txt         /categories
  item-unit.txt          /item-unit
  products.txt           /products
  product-inventory.txt  /prodcut-inventory  (stock of a product in a warehouse)
  customer.txt           /customer
  supplier.txt           /supplier
  employees.txt          /employees


Authentication
--------------
EVERY endpoint requires a JWT, except POST /auth/login (and its twin POST /users/login).
Send it on every request:

    Authorization: Bearer <access_token>

Missing / invalid token -> 401:
    { "message": "Unauthorized", "statusCode": 401 }

First login on a fresh (Docker) database: username "admin", password "admin123"
(a SUPERADMIN created automatically when there are no users).


General rules
-------------
1. Codes are generated by the server. Do NOT send "code" when creating
   branch / category / item-unit / product / customer / supplier / employee.
   If you send one it is ignored. Formats:
     branch-123456, category-123456, unit-123456, PRD-123456,
     CUS-123456, SUP-123456, EMP-123456

2. Money / quantity fields (prices, quantity, creditLimit, openingBalance...)
   are SENT as numbers but RETURNED as strings, e.g. "12.5".
   Convert with Number(...) / parseFloat(...) before doing math.

3. Delete is a SOFT delete (record hidden, not removed) for:
   branch, inventory, products, product-inventory, customer, supplier,
   employees, users.
   Delete is a HARD delete (removed permanently) for: categories, item-unit.

4. IDs are strings (cuid), e.g. "cmwnwbnsj00002fmx5qtqdm7q".

5. Response shapes are NOT the same across modules - check each file.
   Most use { "data": ..., "message": "..." } but products, customer,
   supplier and product-inventory use other keys.

6. PATCH = partial update: send only the fields you want to change.

7. Request bodies are JSON:  Content-Type: application/json


Common error responses
----------------------
400 Validation error ("message" is an ARRAY):
{
  "message": ["name should not be empty", "name must be a string"],
  "error": "Bad Request",
  "statusCode": 400
}

401 Unauthorized:
{ "message": "Unauthorized", "statusCode": 401 }

404 Not found (message differs per module):
{ "statusCode": 404, "message": "Branch with id xxx not found", "error": "Not Found" }

409 Conflict (a unique value is already used - username, email, barcode,
nationalId, employeeId on a user...). "message" names the field:
{ "statusCode": 409, "message": "username already exists", "error": "Conflict" }

400 Related record not found (you sent an id that does not exist, e.g.
categoryId on a product, branchId / employeeId on a user):
{ "statusCode": 400, "message": "categoryId does not exist", "error": "Bad Request" }

500 Internal server error (unexpected server problem only):
{ "statusCode": 500, "message": "Internal server error" }


Typical setup order (because of relations)
------------------------------------------
1. POST /auth/login                       -> token
2. POST /branch                           -> branchId
3. POST /inventory/branch/:branchId       -> inventoryId (warehouse)
4. POST /categories, POST /item-unit      -> categoryId, itemUnitId
5. POST /products                         -> productId
6. POST /prodcut-inventory/inventory/:inventoryId  (put stock in warehouse)
7. POST /employees/branch/:branchId, POST /users, /customer, /supplier
