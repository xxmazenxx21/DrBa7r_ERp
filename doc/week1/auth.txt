Authentication & Authorization API Documentation
================================================

Base URL
--------
Production:      https://drba7rerp-production.up.railway.app
Local (Docker):  http://localhost:3000

Overview
--------
The backend is secured globally with JWT. Every endpoint requires a valid
Bearer token, EXCEPT POST /auth/login (POST /users/login is the same endpoint
and also public - use either one).
There is NO public signup. New users are created by a logged-in user via
POST /users (see users.txt).

First account on a fresh (Docker) database:
    username: admin
    password: admin123
    role:     SUPERADMIN

How to Authenticate
-------------------
Log in, take "access_token" from the response, and send it on every request:

    Authorization: Bearer <access_token>


---------------------------------------------------------
AUTH APIs
---------------------------------------------------------

1) Login
   Method: POST
   URL: /auth/login
   Access: Public (no token needed)
   Description: Checks username/password, updates the user's lastLoginDate,
                and returns a JWT access token.

   Validation Rules:
   - username: required string
   - password: required string

   Request Example:
   {
     "username": "admin",
     "password": "admin123"
   }

   Response Example (201 Created):
   {
     "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
     "user": {
       "id": "cmwnwbnsj00002fmx5qtqdm7q",
       "username": "admin",
       "role": "SUPERADMIN"
     }
   }

   Error Response (401 - wrong username/password, or user is deleted):
   {
     "message": "Invalid credentials",
     "error": "Unauthorized",
     "statusCode": 401
   }

   Error Response (400 - missing fields):
   {
     "message": ["username should not be empty", "username must be a string"],
     "error": "Bad Request",
     "statusCode": 400
   }


---------------------------------------------------------
Roles
---------------------------------------------------------
    SUPERADMIN | ADMIN | ACCOUNTENT | SALES | USER

The role is inside the login response (user.role) and inside the JWT payload
({ sub, username, role }). Use it in the frontend to show/hide screens.


---------------------------------------------------------
Frontend Integration Guide
---------------------------------------------------------

1. Missing / invalid token (401)
   Any protected route called without a token, or with an invalid one, returns:
   {
     "message": "Unauthorized",
     "statusCode": 401
   }
   Action: intercept 401 in your Axios/Fetch client, clear the session,
   and redirect to the Login screen.

2. Role restrictions (403)
   No endpoint is role-restricted yet. When some are, a user without the
   required role will get:
   {
     "message": "You do not have the required roles to access this resource",
     "error": "Forbidden",
     "statusCode": 403
   }
   Action: show a "Permission Denied" toast/alert.

3. Token lifetime
   Tokens are valid for a very long time (3650 days), so in practice the user
   stays logged in until they log out (delete the token on the frontend).
