Product Inventory API Documentation
===================================

Base URL
--------
Production:      https://drba7rerp-production.up.railway.app
Local (Docker):  http://localhost:3000

Authentication & access
-----------------------
All endpoints require:  Authorization: Bearer <access_token>   (see auth.txt)
Only SUPERADMIN can call them:
  - no / invalid token  -> 401 { "message": "Unauthorized", "statusCode": 401 }
  - other roles         -> 403 { "message": "You do not have the required roles to access this resource", "error": "Forbidden", "statusCode": 403 }

Response shape: every success is { "message": "...", "data": ... }
Unknown fields in a body -> 400 "property <name> should not exist"
Delete is a SOFT delete (record hidden, kept in the database).

A product-inventory record = the stock of ONE product inside ONE inventory
(warehouse): quantity + cost price. A product can only have one record per
inventory. Deleting it and adding the same product again RESTORES the old
record (see Create).

NOTE: the URL is spelled "prodcut-inventory" (this is the real path).
NOTE: quantity / costPrice are sent as numbers but returned as strings, with
      up to 4 decimals (100.12345 is stored as "100.1235").

Product inventory object (what "data" contains)
-----------------------------------------------
{
  "id": "cm4prodinv123",
  "productId": "cm4product123",
  "inventoryId": "cm4inventory789",
  "quantity": "100",
  "costPrice": "12.5",
  "deletedAt": null
}

---------------------------------------------------------
PRODUCT INVENTORY APIs
---------------------------------------------------------

1) Create Product Inventory Record
   Method: POST
   URL: /prodcut-inventory/inventory/:inventoryId
   Description: Puts a product into an inventory with a quantity and cost price.
                If this product was in this inventory before and that record
                was DELETED, the same record is restored (same id) with the new
                quantity and costPrice. Status is 201 in both cases; only the
                message is different.

   Path Parameters:
   - inventoryId: required string (id from GET /inventory/branch/:branchId)

   Validation Rules:
   - productId: required string
   - quantity: required number, minimum 0
   - costPrice: required number, minimum 0
   - inventoryId: optional, IGNORED (the one in the URL is used)

   Request Example:
   POST /prodcut-inventory/inventory/cm4inventory789
   {
     "productId": "cm4product123",
     "quantity": 100,
     "costPrice": 12.5
   }

   Response Example (201 - new record):
   {
     "message": "Product inventory created successfully",
     "data": { ...product inventory object }
   }

   Response Example (201 - a deleted record was restored):
   {
     "message": "Product inventory restored successfully",
     "data": {
       "id": "cm4prodinv123",          <-- the OLD record's id
       "productId": "cm4product123",
       "inventoryId": "cm4inventory789",
       "quantity": "42",               <-- values from this request
       "costPrice": "7.25",
       "deletedAt": null
     }
   }

   Error Responses:
   - 404 { "statusCode": 404, "message": "Inventory not found", "error": "Not Found" }
   - 404 { "statusCode": 404, "message": "Product not found", "error": "Not Found" }
   - 400 { "statusCode": 400, "message": "Product inventory already exists", "error": "Bad Request" }
         (this product already has an ACTIVE record in this inventory -> use PATCH instead)

2) Get All Products in an Inventory
   Method: GET
   URL: /prodcut-inventory/inventory/:inventoryId
   Description: All active stock records of an inventory (deleted products are
                excluded), each with the full product + category + unit.

   Response Example (200):
   {
     "message": "Products in inventory fetched successfully",
     "data": [
       {
         ...product inventory object,
         "product": {
           ...product object (see products.txt),
           "category": { ...category object },
           "primaryIteamUnit": { ...item unit object }
         }
       }
     ]
   }

   Error Response (404):
   {
     "statusCode": 404,
     "message": "Inventory with id cm4inventory789 not found",
     "error": "Not Found"
   }

3) Get Single Product Inventory Record
   Method: GET
   URL: /prodcut-inventory/:id
   Description: One stock record with the full product (+ category, unit) and
                its inventory.

   Response Example (200):
   {
     "message": "Product inventory item fetched successfully",
     "data": {
       ...product inventory object,
       "product": {
         ...product object,
         "category": { ...category object },
         "primaryIteamUnit": { ...item unit object }
       },
       "inventory": { ...inventory object (see inventory.txt) }
     }
   }

   Error Response (404):
   {
     "statusCode": 404,
     "message": "Product inventory with ID cm4prodinv123 not found",
     "error": "Not Found"
   }

4) Update Product Inventory Record
   Method: PATCH
   URL: /prodcut-inventory/:id
   Description: Sets quantity and/or costPrice directly. Intended for MANUAL
                CORRECTION (e.g. a wrong opening quantity or cost entered by
                mistake). Only quantity and costPrice are changed.

   Request Example:
   {
     "quantity": 150,
     "costPrice": 13.0
   }

   Response Example (200):
   {
     "message": "Product inventory updated successfully",
     "data": {
       "id": "cm4prodinv123",
       "productId": "cm4product123",
       "inventoryId": "cm4inventory789",
       "quantity": "150",
       "costPrice": "13",
       "deletedAt": null
     }
   }

   Error Response (404): same as Get Single Product Inventory Record.

5) Delete Product Inventory Record
   Method: DELETE
   URL: /prodcut-inventory/:id
   Description: Soft delete (sets deletedAt).

   Response Example (200):
   {
     "message": "Product inventory deleted successfully",
     "data": null
   }

   Error Response (404): same as Get Single Product Inventory Record.
