Product Inventory API Documentation
===================================

Base URL
--------
Production:      https://drba7rerp-production.up.railway.app
Local (Docker):  http://localhost:3000

Authentication & access
-----------------------
All endpoints require:  Authorization: Bearer <access_token>   (see auth.txt)
Only SUPERADMIN can call them:
  - no / invalid token  -> 401 { "statusCode": 401, "message": "Unauthorized", "error": "Unauthorized", "code": "UNAUTHORIZED", "field": null }
  - other roles         -> 403 { "statusCode": 403, "message": "You do not have the required roles to access this resource", "error": "Forbidden", "code": "FORBIDDEN", "field": null }

Response shape: every success is { "message": "...", "data": ... }
Every error has { statusCode, message, error, code, field } (see 00-overview.txt)
Unknown fields in a body -> 400 "property <name> should not exist"
Delete is a SOFT delete (record hidden, kept in the database).

A product-inventory record = the stock of ONE product inside ONE inventory
(warehouse): quantity + cost price. A product can only have one record per
inventory. Deleting it and adding the same product again RESTORES the old
record (see Create).

WEEK 2 - every change here is now recorded as a STOCK MOVEMENT (item card /
كارت الصنف, see doc/week2/stock.txt):
  POST   -> OPENING movement     (رصيد افتتاحي) with the quantity / cost
  PATCH  -> ADJUSTMENT movement  (تسوية) with the DIFFERENCE; needs "reason"
  DELETE -> if there is stock: ADJUSTMENT to 0 (reason "حذف الصنف من المخزن"),
            then the soft delete. A deleted record always has quantity 0.
costPrice is the product's AVERAGE cost in this warehouse (purchases update it).
SERVICE products (itemType SERVICE) can't be put in a warehouse (400).

NOTE: quantity / costPrice are sent as numbers but returned as strings.
      Max 4 decimal places: 100.1234 is OK, 100.12345 -> 400 (never rounded):
      { "statusCode": 400, "message": ["quantity must have at most 4 decimal places"], "error": "Bad Request", "code": "VALIDATION_FAILED", "field": "quantity" }

Product inventory object (what "data" contains)
-----------------------------------------------
{
  "id": "cm4prodinv123",
  "productId": "cm4product123",
  "inventoryId": "cm4inventory789",
  "quantity": "100",
  "costPrice": "12.5",
  "deletedAt": null
}

---------------------------------------------------------
PRODUCT INVENTORY APIs
---------------------------------------------------------

1) Create Product Inventory Record
   Method: POST
   URL: /product-inventory/inventory/:inventoryId
   Description: Puts a product into an inventory with a quantity and cost price.
                If this product was in this inventory before and that record
                was DELETED, the same record is restored (same id) with the new
                quantity and costPrice. Status is 201 in both cases; only the
                message is different.

   Path Parameters:
   - inventoryId: required string (id from GET /inventory/branch/:branchId)

   Validation Rules:
   - productId: required string (id of an ACTIVE product)
   - quantity: required number, minimum 0, max 4 decimal places
   - costPrice: required number, minimum 0, max 4 decimal places
   - inventoryId: optional, IGNORED (the one in the URL is used)

   Request Example:
   POST /product-inventory/inventory/cm4inventory789
   {
     "productId": "cm4product123",
     "quantity": 100,
     "costPrice": 12.5
   }

   Response Example (201 - new record):
   {
     "message": "Product inventory created successfully",
     "data": { ...product inventory object }
   }

   Response Example (201 - a deleted record was restored):
   {
     "message": "Product inventory restored successfully",
     "data": {
       "id": "cm4prodinv123",          <-- the OLD record's id
       "productId": "cm4product123",
       "inventoryId": "cm4inventory789",
       "quantity": "42",               <-- values from this request
       "costPrice": "7.25",
       "deletedAt": null
     }
   }

   Error Responses:
   - 404 { "statusCode": 404, "message": "Inventory not found", "error": "Not Found", "code": "NOT_FOUND", "field": null }
   - 400 { "statusCode": 400, "message": "productId does not exist", "error": "Bad Request", "code": "DOES_NOT_EXIST", "field": "productId" }
         (productId missing OR deleted. Was 404 "Product not found" before UPDATE 3)
   - 400 { "statusCode": 400, "message": "Product inventory already exists", "error": "Bad Request", "code": "ALREADY_EXISTS", "field": "productId" }
         (this product already has an ACTIVE record in this inventory -> use PATCH instead)
   - 400 SERVICE product (Week 2)
         { "statusCode": 400, "message": "Service items (SERVICE) have no stock", "error": "Bad Request", "code": "BAD_REQUEST", "field": "productId" }

   Writes an OPENING movement (if quantity or cost is not 0).

2) Get All Products in an Inventory
   Method: GET
   URL: /product-inventory/inventory/:inventoryId
   Description: All active stock records of an inventory (deleted products are
                excluded), each with the full product + category + unit.

   Response Example (200):
   {
     "message": "Products in inventory fetched successfully",
     "data": [
       {
         ...product inventory object,
         "product": {
           ...product object (see products.txt),
           "category": { ...category object },
           "primaryItemUnit": { ...item unit object }
         }
       }
     ]
   }

   Error Response (404):
   {
     "statusCode": 404,
     "message": "Inventory with id cm4inventory789 not found",
     "error": "Not Found",
     "code": "NOT_FOUND",
     "field": null
   }

3) Get Single Product Inventory Record
   Method: GET
   URL: /product-inventory/:id
   Description: One stock record with the full product (+ category, unit) and
                its inventory.

   Response Example (200):
   {
     "message": "Product inventory item fetched successfully",
     "data": {
       ...product inventory object,
       "product": {
         ...product object,
         "category": { ...category object },
         "primaryItemUnit": { ...item unit object }
       },
       "inventory": { ...inventory object (see inventory.txt) }
     }
   }

   Error Response (404):
   {
     "statusCode": 404,
     "message": "Product inventory with ID cm4prodinv123 not found",
     "error": "Not Found",
     "code": "NOT_FOUND",
     "field": null
   }

4) Update Product Inventory Record
   Method: PATCH
   URL: /product-inventory/:id
   Description: Sets quantity and/or costPrice directly. Intended for MANUAL
                CORRECTION (stock count / جرد, a wrong opening quantity or cost).
                Only quantity and costPrice are changed.
                Same limits as Create (min 0, max 4 decimals); null -> 400.
                WEEK 2 (BREAKING): writes an ADJUSTMENT movement with the
                difference (150 -> 140 = -10), and "reason" is REQUIRED when
                quantity or costPrice really changes:
                - reason: string, not empty, max 250 characters (السبب)
                Sending the same values (nothing changes) needs no reason and
                writes no movement.

   Request Example:
   {
     "quantity": 150,
     "costPrice": 13.0,
     "reason": "جرد"
   }

   Response Example (200):
   {
     "message": "Product inventory updated successfully",
     "data": {
       "id": "cm4prodinv123",
       "productId": "cm4product123",
       "inventoryId": "cm4inventory789",
       "quantity": "150",
       "costPrice": "13",
       "deletedAt": null
     }
   }

   Error Response (404): same as Get Single Product Inventory Record.
   Error Response (400 - something changes but no reason):
   {
     "statusCode": 400,
     "message": ["reason is required when quantity or costPrice changes"],
     "error": "Bad Request",
     "code": "VALIDATION_FAILED",
     "field": "reason"
   }
   Error Response (400 - a SERVICE product can't get stock): same body as Create.

5) Delete Product Inventory Record
   Method: DELETE
   URL: /product-inventory/:id
   Description: Soft delete (sets deletedAt). If the record still has stock,
                it is first set to 0 with an ADJUSTMENT movement (reason
                "حذف الصنف من المخزن"), so the item card stays correct.

   Response Example (200):
   {
     "message": "Product inventory deleted successfully",
     "data": null
   }

   Error Response (404): same as Get Single Product Inventory Record.
