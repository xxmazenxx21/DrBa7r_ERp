Users API Documentation
=======================

Base URL
--------
http://localhost:3000   (the backend runs on your machine with Docker, see README.md)

Authentication & access
-----------------------
All endpoints require:  Authorization: Bearer <access_token>   (see auth.txt)
Only SUPERADMIN can call them:
  - no / invalid token  -> 401 { "statusCode": 401, "message": "Unauthorized", "error": "Unauthorized", "code": "UNAUTHORIZED", "field": null }
  - other roles         -> 403 { "statusCode": 403, "message": "You do not have the required roles to access this resource", "error": "Forbidden", "code": "FORBIDDEN", "field": null }

Response shape: every success is { "message": "...", "data": ... }
Every error has { statusCode, message, error, code, field } (see 00-overview.txt)
Unknown fields in a body -> 400 "property <name> should not exist"
Delete is a SOFT delete (record hidden, kept in the database).
EXCEPTION: POST /users/login is public (no token, any role).

Overview
--------
Users are the accounts that log into the ERP. A user can optionally be linked
to an Employee and/or a Branch, and always has one Role.
The password is NEVER returned by any endpoint.

Branch rule (user <-> employee):
  A user linked to an employee is ALWAYS in the employee's branch.
  - employeeId sent, branchId NOT sent -> branchId is filled from the employee
  - both sent and different            -> 400 "branchId must match the employee's branch"
  - PATCH branchId only, on a user that already has an employee -> checked
    against that employee (different -> same 400)
  - no employee                        -> branchId is free (optional)

Role values (field "role")
--------------------------
    SUPERADMIN | ADMIN | ACCOUNTANT | SALES | USER

User object (what "data" contains)
----------------------------------
{
  "id": "cm4user123",
  "username": "ahmed.sales",
  "email": "ahmed@example.com",
  "role": "SALES",
  "employeeId": "cm4employee789",
  "branchId": "cm4branch123",
  "lastLoginDate": null,          <-- null until the user logs in for the first time
  "createdAt": "2026-08-21T18:25:33.000Z",
  "updatedAt": "2026-08-21T18:25:33.000Z"
}


---------------------------------------------------------
1) Create User
---------------------------------------------------------
Method: POST
URL: /users

Validation Rules:
- username   : required, 3-30 characters, only letters (A-Z a-z), digits,
               dot (.), underscore (_), dash (-). NO spaces, no Arabic letters.
               Spaces at the start/end are trimmed. Must be unique.
- password   : required string, minimum 6 characters (stored hashed)
- role       : required, one of the role values above
- email      : optional, valid email (must be unique)
- employeeId : optional string (id of an ACTIVE employee; one user per employee)
- branchId   : optional string (id of an ACTIVE branch). With an employeeId:
               leave it out (filled from the employee) or send the same branch.

Request Example:
{
  "username": "ahmed.sales",
  "password": "secret123",
  "role": "SALES",
  "email": "ahmed@example.com",
  "employeeId": "cm4employee789",
  "branchId": "cm4branch123"
}

Success Response (201):
{
  "message": "user created successfully",
  "data": { ...user object (see above), lastLoginDate: null }
}

Error Cases:
- Missing/invalid/unknown fields              -> 400 (validation error)
- Bad username                                -> 400
    {
      "statusCode": 400,
      "message": ["username must be 3-30 characters: letters, digits, dot, underscore or dash only (no spaces)"],
      "error": "Bad Request",
      "code": "VALIDATION_FAILED",
      "field": "username"
    }
- Duplicate username / email / employeeId of an ACTIVE user -> 409
    { "statusCode": 409, "message": "username already exists", "error": "Conflict", "code": "ALREADY_EXISTS", "field": "username" }
    (message is "email already exists" / "employeeId already exists" accordingly)
- username / email / employeeId of a DELETED user -> 409 (the user is NOT restored)
    { "statusCode": 409, "message": "username belongs to a deleted user", "error": "Conflict", "code": "BELONGS_TO_DELETED", "field": "username" }
    (or "email belongs to a deleted user" / "employeeId belongs to a deleted user")
- employeeId or branchId that does not exist OR is deleted -> 400
    { "statusCode": 400, "message": "branchId does not exist", "error": "Bad Request", "code": "DOES_NOT_EXIST", "field": "branchId" }
    { "statusCode": 400, "message": "employeeId does not exist", "error": "Bad Request", "code": "DOES_NOT_EXIST", "field": "employeeId" }
- branchId different from the employee's branch -> 400
    { "statusCode": 400, "message": "branchId must match the employee's branch", "error": "Bad Request", "code": "BAD_REQUEST", "field": "branchId" }


---------------------------------------------------------
2) Get All Users
---------------------------------------------------------
Method: GET
URL: /users
Description: All active (not deleted) users.

Success Response (200):
{
  "message": "Users retrieved successfully",
  "data": [ { ...user object }, { ...user object } ]
}


---------------------------------------------------------
3) Get User By ID
---------------------------------------------------------
Method: GET
URL: /users/:id

Success Response (200):
{
  "message": "User retrieved successfully",
  "data": { ...user object }
}

Error Response (404 - not found or deleted):
{
  "statusCode": 404,
  "message": "User with id cm4user123 not found",
  "error": "Not Found",
  "code": "NOT_FOUND",
  "field": null
}


---------------------------------------------------------
4) Update User
---------------------------------------------------------
Method: PATCH
URL: /users/:id
Description: Partial update. Allowed fields: username, password, role,
email, employeeId, branchId (all optional).
Sending "password" changes the user's password (min 6 characters, stored hashed).
null CLEARS a nullable field:
  "email": null       -> removes the email
  "employeeId": null  -> unlinks the employee (branchId is kept)
  "branchId": null    -> removes the branch (400 if the user still has an employee)
null on username / password / role -> 400.
The branch rule above applies (employeeId only -> branch follows the employee).

Request Example (change role and email):
{
  "role": "ADMIN",
  "email": "newmail@example.com"
}

Request Example (change password):
{
  "password": "newpass123"
}

Request Example (link to another employee; branchId follows automatically):
{
  "employeeId": "cm4employee999"
}

Success Response (200):
{
  "message": "User updated successfully",
  "data": { ...updated user object }
}

Error Cases:
- User not found / deleted                            -> 404 (same body as Get User By ID)
- Invalid role / bad email / bad username / password shorter than 6 -> 400
- username / email / employeeId used by an active or a deleted user -> 409 (same bodies as Create)
- employeeId or branchId that does not exist or is deleted -> 400 DOES_NOT_EXIST (same body as Create)
- branchId different from the employee's branch       -> 400 (same body as Create)


---------------------------------------------------------
5) Delete User
---------------------------------------------------------
Method: DELETE
URL: /users/:id
Description: Soft delete. The user disappears from lists and can no longer log in.

Success Response (200):
{
  "message": "User deleted successfully",
  "data": null
}

Error Response (404 - not found or already deleted): same as Get User By ID.


---------------------------------------------------------
6) Login
---------------------------------------------------------
Method: POST
URL: /users/login
Access: Public (no token needed)
Description: Exactly the same as POST /auth/login - same body, same response,
same errors (see auth.txt). Spaces around the username are trimmed.

Request Example:
{
  "username": "admin",
  "password": "admin123"
}

Success Response (201):
{
  "message": "Logged in successfully",
  "data": {
    "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "user": {
      "id": "cm4user123",
      "username": "admin",
      "role": "SUPERADMIN"
    }
  }
}

Error Response (401 - wrong username/password, or user is deleted):
{
  "statusCode": 401,
  "message": "Invalid credentials",
  "error": "Unauthorized",
  "code": "UNAUTHORIZED",
  "field": null
}


---------------------------------------------------------
Related APIs you need BEFORE calling POST /users
---------------------------------------------------------
A) branchId:   GET /branch                       -> data[i].id
B) employeeId: GET /branch                       -> pick a branch id
               GET /employees/branch/{branchId}  -> data[i].id
