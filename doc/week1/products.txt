Products API Documentation
==========================

Base URL
--------
Production:      https://drba7rerp-production.up.railway.app
Local (Docker):  http://localhost:3000

Authentication & access
-----------------------
All endpoints require:  Authorization: Bearer <access_token>   (see auth.txt)
Only SUPERADMIN can call them:
  - no / invalid token  -> 401 { "statusCode": 401, "message": "Unauthorized", "error": "Unauthorized", "code": "UNAUTHORIZED", "field": null }
  - other roles         -> 403 { "statusCode": 403, "message": "You do not have the required roles to access this resource", "error": "Forbidden", "code": "FORBIDDEN", "field": null }

Response shape: every success is { "message": "...", "data": ... }
Every error has { statusCode, message, error, code, field } (see 00-overview.txt)
Unknown fields in a body -> 400 "property <name> should not exist"
Delete is a SOFT delete (record hidden, kept in the database).

NOTE: price fields are sent as numbers but returned as strings ("12.5").
      Max 4 decimal places: 12.3457 is OK, 12.34567 -> 400 (never rounded):
      { "statusCode": 400, "message": ["retailPrice must have at most 4 decimal places"], "error": "Bad Request", "code": "VALIDATION_FAILED", "field": "retailPrice" }

Enum fields (send / receive the TEXT value, not a number):
    itemType       STOCK            = مخزني  (kept in warehouses)   <- default
                   SERVICE          = خدمي   (a service, no stock)
    costingMethod  WEIGHTED_AVERAGE = متوسط التكلفة المرجح           <- default (only value for now)
Any other value -> 400 VALIDATION_FAILED, e.g.
    { "statusCode": 400, "message": ["itemType must be one of the following values: STOCK, SERVICE"], "error": "Bad Request", "code": "VALIDATION_FAILED", "field": "itemType" }

---------------------------------------------------------
PRODUCTS APIs
---------------------------------------------------------

1) Create Product
   Method: POST
   URL: /products

   Validation Rules:
   - name: required string
   - categoryId: required string (id from GET /categories)
   - primaryItemUnitId: required string (id from GET /item-unit)
   - itemType: optional, "STOCK" or "SERVICE" (default "STOCK")
   - retailPrice: required number, minimum 0, max 4 decimal places
   - wholesalePrice: required number, minimum 0, max 4 decimal places
   - bulkWholesalePrice: required number, minimum 0, max 4 decimal places
   - barcode: optional string (must be unique)
   - costingMethod: optional, "WEIGHTED_AVERAGE" (default "WEIGHTED_AVERAGE")
   - reorderLimit: optional number, minimum 0, max 4 decimal places (default 0)
   - itemType / costingMethod / reorderLimit / hasExpiryDate: null -> 400
     (leave the field out to get the default)
   - hasExpiryDate: optional boolean (default false)
   - code: do NOT send (generated by the server as "PRD-XXXXXX"; ignored if sent)

   Request Example:
   {
     "barcode": "6221234567890",
     "name": "بيبسي 330 مل",
     "categoryId": "cm4category123",
     "primaryItemUnitId": "cm4unit123",
     "itemType": "STOCK",
     "costingMethod": "WEIGHTED_AVERAGE",
     "retailPrice": 15.0,
     "wholesalePrice": 12.5,
     "bulkWholesalePrice": 10.0,
     "reorderLimit": 50,
     "hasExpiryDate": true
   }

   Response Example (201):
   {
     "message": "Product created successfully",
     "data": { ...product object }
   }

   Error Responses:
   - 400 validation error (missing / invalid / unknown fields)
   - 400 category or unit does not exist OR is deleted:
     { "statusCode": 400, "message": "categoryId does not exist", "error": "Bad Request", "code": "DOES_NOT_EXIST", "field": "categoryId" }
     { "statusCode": 400, "message": "primaryItemUnitId does not exist", "error": "Bad Request", "code": "DOES_NOT_EXIST", "field": "primaryItemUnitId" }
   - 409 barcode already used by another ACTIVE product:
     { "statusCode": 409, "message": "barcode already exists", "error": "Conflict", "code": "ALREADY_EXISTS", "field": "barcode" }
   - 409 barcode belongs to a DELETED product (the product is NOT restored):
     { "statusCode": 409, "message": "barcode belongs to a deleted product", "error": "Conflict", "code": "BELONGS_TO_DELETED", "field": "barcode" }

4) Update Product
   Method: PATCH
   URL: /products/:id
   Description: Partial update. Any field from Create (except code) is allowed.
                "barcode": null CLEARS the barcode (the only nullable field).
                null on any other field -> 400.

   Request Example:
   {
     "name": "بيبسي 330 مل - سعر جديد",
     "retailPrice": 18.0
   }

   Response Example:
   {
     "message": "Product updated successfully",
     "data": { ...updated product object (no category / unit included) }
   }

   Error Responses:
   - 404 same as Get Product By ID
   - 400 new categoryId / primaryItemUnitId does not exist or is deleted (same body as Create)
   - 409 barcode used by another active or deleted product (same bodies as Create)
   - 400 itemType "SERVICE" while the product is still in a warehouse (Week 2)
     { "statusCode": 400, "message": "itemType can't be SERVICE while the product is in a warehouse; remove it from the warehouses first", "error": "Bad Request", "code": "BAD_REQUEST", "field": "itemType" }
     (DELETE its /product-inventory records first)
   - 400 primaryItemUnitId changed to a DIFFERENT unit after the product was used (Week 2)
     { "statusCode": 400, "message": "primaryItemUnitId can't change: stock and units are stored in the current primary unit", "error": "Bad Request", "code": "BAD_REQUEST", "field": "primaryItemUnitId" }
     The primary unit is LOCKED as soon as the product has:
       - ANY stock movement (it was ever put in a warehouse with a quantity /
         cost, see doc/week2/stock.txt). Movements are permanent, so this
         stays locked even after the stock is deleted, or
       - ANY active product unit (carton = 12..., see doc/week2/product-units.txt).
     Why: every stored quantity and every unit factor is counted in the primary
     unit (12 = 12 PIECES); changing it would silently change all of them.
     Sending the SAME primaryItemUnitId it already has is allowed.
     A new product with no stock and no units can still change it freely.
     Arabic: لا يمكن تغيير الوحدة الأساسية بعد استخدام الصنف (له حركات مخزن أو وحدات)

5) Delete Product
   Method: DELETE
   URL: /products/:id
   Description: Soft delete (sets deletedAt).

   Response Example:
   {
     "message": "Product deleted successfully",
     "data": null
   }

   Error Response (404): same as Get Product By ID.
